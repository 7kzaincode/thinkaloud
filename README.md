# thinkaloud

A weekend prototype of a think-aloud trajectory recorder. An expert does a real task on their
computer while talking through it. thinkaloud records what they did (clicks, typing, scrolls,
screenshots) and why (their narration), lines the two up step by step, checks the result for
problems, and gives a reviewer a UI to fix it and sign off on it. The output is a
`trajectory.json` that could be used as computer-use training data.

## Why

I built this while applying to AfterQuery, who sell expert-demonstrated computer-use trajectories and
reasoning data to AI labs. Their pitch is that models trained on outputs plateau, while models trained
on reasoning keep improving. I wanted to see how hard it is to capture reasoning cleanly, so I built a
very small version.

It comes out of an earlier project, teachAR, which recorded an expert's hand movements in VR so a
learner could follow along. Recording the motion was the easy part. The hard part was knowing
whether the task had actually been done right. So thinkaloud also records **what "done" means**:
before recording, the expert states success criteria, and a reviewer checks the final screen against
them. A trajectory marked *Task done* is a positive demonstration. One without that mark is just a
recording.

## The loop

```
record.py  ──►  sessions/<ts>/            ──►  python -m thinkaloud  ──►  trajectory.json  ──►  viewer
(desktop)       events.jsonl, audio.wav,       (Docker or local)           + QC flags            (Next.js)
                frames/*.png, meta.json        whisper → steps → align → QC                     edit, flag, pass/fail,
                                                                                                  export
```

| Part | Where | What it does |
|---|---|---|
| Recorder | `recorder/record.py` | Captures clicks, keys, scrolls, screenshots (start, end, every click, Enter/Tab) and 16 kHz mic audio. F9 stops. |
| Processor | `processor/thinkaloud/` | faster-whisper transcription, event → step merging, narration alignment, quality checks, redaction, export. |
| Viewer | `viewer/` | Local Next.js app for stepping through a session, editing reasoning, dismissing or raising flags, marking the outcome, and exporting. |
| Sample | `samples/synthetic-flight/` | A fake 72-second session (generated by `scripts/make_synthetic.py`) that trips every QC rule, so you can try everything without recording. |

## Running it

Requires Python 3.11+ and Node 20+. Tested on Windows 11 with Python 3.12 and Node 22.

```bash
python -m venv .venv
.venv/Scripts/pip install -r recorder/requirements.txt -r processor/requirements-dev.txt   # macOS/Linux: .venv/bin/pip
```

**1. Record** (or skip to step 2 and use the sample)

```bash
.venv/Scripts/python recorder/record.py --task "Find the cheapest nonstop YYZ→SFO flight on Oct 17" --criteria "Checkout shows the cheapest nonstop flight"
```

Talk the whole time: say what you're about to do and why. Press **F9** to stop. Check that your
default input device is your real microphone, not a virtual one. If you have several monitors,
`--monitor 1` is the primary.

**2. Process**

```bash
cd processor
../.venv/Scripts/python -m thinkaloud ../sessions            # every session under sessions/
../.venv/Scripts/python -m thinkaloud ../samples/synthetic-flight
../.venv/Scripts/python -m thinkaloud ../sessions/2026-09-26T14-03-11 --transcript my_transcript.json   # skip Whisper
```

Or with Docker, which is what the processor is meant to run in:

```bash
docker build -t thinkaloud-processor processor
docker run --rm -v "$PWD/sessions:/data" -v thinkaloud-models:/models thinkaloud-processor /data
docker build --build-arg WITH_OCR=1 -t thinkaloud-processor:ocr processor     # adds Tesseract for --ocr
```

It prints a summary and every non-info flag:

```
QC: 18 steps, 1 missing reasoning, 1 idle gap, 1 possible secret, 1 typed email
  step   1 [high] possible_email: Typed text contains an email address.
  step   3 [high] possible_secret: Typed text may be a password: single token mixing letters, digits and symbols.
  step  16 [warn] missing_reasoning: No narration aligned to this step.
  step  16 [warn] idle_gap: 23.6s with no actions before this step (silent)
```

`--strict` exits 1 if any high-severity flag is left, which is handy as a gate in a pipeline.

**3. Review**

```bash
cd viewer && npm install && npm run dev      # http://localhost:3217
```

The viewer reads `../sessions` and `../samples` (override with `THINKALOUD_DIRS`). Edits autosave to
`trajectory.reviewed.json` next to the original. The processor's `trajectory.json` is never
overwritten. **Export JSON** downloads the reviewed trajectory. Keys: `←`/`→` step, `n` next flag,
`e` end state.

**Tests**

```bash
cd processor && ../.venv/Scripts/python -m pytest -q
.venv/Scripts/python scripts/smoke_record.py    # real recorder on your desktop: opens a Tk window, clicks and types in it, presses F9
```

## How steps are built

Raw events → steps (`processor/thinkaloud/steps.py`):

- Printable keys typed with gaps of 2 s or less become one **type** step. Backspace edits the text, so the step holds what was finally in the box.
- **Enter** and **Tab** end a typing burst and become their own **key** step, with a screenshot.
- Ctrl/Alt/Win combos become **key** steps like `ctrl+c`. Repeats of the same special key within 1 s merge (`repeat: 3`).
- Consecutive scrolls with gaps of 1.5 s or less merge into one **scroll** step with summed `dx`/`dy`.
- Each click is a **click** step. Two clicks at the same spot within 0.4 s count as a double-click (`count: 2`).
- A step's screenshot is the most recent frame at or before the step started: **what the expert was looking at when they acted**.

## How narration is aligned

People usually say what they're about to do, then do it (`align.py`):

1. A transcript segment goes to the **first step that starts within [segment start, segment end + 4 s]**.
2. If no step starts in that window, it goes to the **last step that started before the segment ended** (commentary after the fact).
3. If there's no such step either, it stays unassigned. It's kept in the transcript and QC reports it.

**Carry-forward:** one sentence of intent often covers several actions. "Now the search, I use airport
codes" covers four steps: click, type, click, type. A step with no narration of its own inherits the
previous step's reasoning if it starts within 6 s of that step ending. It's marked
`reasoning_source: "carried"` with `carried_from`, and the viewer shows it in grey italics. Without
this, 10 of the 18 sample steps were flagged "missing reasoning", which was accurate but useless.
With it, the only step flagged is the one that really is unexplained.

## Quality checks

| Code | Severity | Rule |
|---|---|---|
| `possible_email` | high | Typed text matches an email regex. Text is **redacted** in the export. |
| `possible_secret` | high | Typed text is a single 6–64 char token and either mixes 3+ character classes, or nearby narration says password/pin/secret/token, or it was typed right after an email (login form). **Redacted.** |
| `email_in_screenshot` | high | `--ocr` only: Tesseract finds an email address in the step's screenshot. |
| `missing_reasoning` | warn | No narrated or carried reasoning. |
| `idle_gap` | warn / info | More than 20 s with no actions before this step. **warn** if silent, **info** if the expert was talking (thinking aloud is fine). |
| `missing_success_criteria`, `missing_task`, `no_final_screenshot`, `no_narration` | warn | Session-level: the outcome can't be judged. |
| `unassigned_narration` | info | Narration before the first action. |

Reviewers can dismiss any flag. Dismissed flags move to `dismissed_flags` rather than being deleted, so
there's an audit trail. Reviewers can also raise their own (`reviewer_flag`). Writing reasoning into
a step auto-resolves its `missing_reasoning`.

## trajectory.json (schema v0.1)

```jsonc
{
  "schema_version": "0.1",
  "session_id": "2026-09-26T14-03-11",
  "task": "Find and select the cheapest nonstop flight YYZ→SFO on Oct 17.",
  "success_criteria": "Checkout page shows the cheapest nonstop YYZ-SFO flight on Oct 17.",
  "recorded_at": "2026-09-26T14:03:11-04:00",
  "duration_s": 71.5,
  "screen": { "w": 2560, "h": 1440 },          // click x/y are pixels in this frame
  "final_screenshot": "frames/000071500.png",  // what the reviewer checks against success_criteria
  "steps": [
    {
      "id": 5,
      "t_start": 13.6, "t_end": 13.6,           // seconds since recording start
      "action": { "type": "click", "x": 230, "y": 293, "button": "left" },
      //   | { "type": "type", "text": "YYZ" }          ("[REDACTED]" + "redacted": true if flagged)
      //   | { "type": "key", "key": "enter" }          ("ctrl+c", "repeat": n)
      //   | { "type": "scroll", "x", "y", "dx", "dy" }
      "screenshot": "frames/000013600.png",
      "reasoning": "Now the search. I use airport codes, not city names, since Toronto has two airports and I want Pearson.",
      "reasoning_source": "narrated",            // "narrated" | "carried" | "reviewer" | null
      "carried_from": null,
      "transcript_ids": [1],
      "flags": [ { "code": "idle_gap", "severity": "warn", "detail": "...", "source": "qc" } ],
      "dismissed_flags": [],                     // written by the viewer
      "edited": false                            // written by the viewer
    }
  ],
  "transcript": [ { "id": 1, "t_start": 10.1, "t_end": 13.2, "text": "...", "step_id": 5 } ],
  "session_flags": [],
  "qc": { "summary": "18 steps, 1 missing reasoning, ...", "counts": { "idle_gap": 1 }, "high_severity": 2, "redacted_steps": 2 },
  "review": { "outcome": "pass", "reviewer": null, "notes": "", "edited": true, "reviewed_at": "..." }
}
```

## Privacy

- `sessions/`, `*.wav`, `frames/`, raw `events.jsonl` and reviewed exports are gitignored. The only frames in the repo are the synthetic sample's.
- Typed emails and likely passwords are redacted in `trajectory.json` by default (`--no-redact` to keep them). **The raw keystrokes are still in the local `events.jsonl`.** The recorder is a keylogger while it runs, so only record what you'd be comfortable having logged.
- Screenshots are not redacted. `--ocr` finds visible emails but doesn't blur them.

## Known limitations

This is a weekend prototype. Things I know are wrong or missing:

- **Password detection is a heuristic.** It catches `Hunter2!x`-style tokens and login-form patterns. It misses a password like `correct horse battery staple` (has spaces) and will occasionally flag a product code. The recorder can't see which field has focus, so it can't read `type="password"`.
- **Alignment is time-based only.** If someone narrates something unrelated ("ugh, this site is slow"), it gets attached to the next action anyway. The 4 s lookahead and 6 s carry window were tuned on one synthetic session and a few of my own recordings, not on real data.
- **Screenshots are event-triggered.** There's no video, so anything that changes between clicks (hover menus, loading states, animations) isn't captured. Scroll steps reuse the last frame.
- **One monitor at a time.** Clicks on other monitors are still logged, with coordinates outside the frame.
- **No window/app context.** A real version would log the focused window title and URL (and the accessibility tree) for every step.
- **Whisper timestamps drift** by a few hundred ms, and `base.en` makes mistakes on jargon. `--model small.en` is better and slower.
- **The recorder can't tell where typing went**, so text typed into the wrong window still becomes a "type" step.
- **The Docker image hasn't been built on my machine yet** (Docker Desktop was broken during the build). The processor was tested in a local venv with the same pinned versions.
